# Changelog

Все заметные изменения WARPScoutGUI-AWG фиксируются здесь; порядок — обратный хронологический, дата версии = дата релизного коммита в git.

Политика выпуска (с 2.5.0): каждый релиз содержит артефакты всех поддерживаемых платформ под единым номером версии — с указанием, что изменено на каждой платформе, либо с явной фиксацией отсутствия изменений; все выпуски 2.5.x публикуются на GitHub со статусом prerelease (блок «Политика выпуска» — `desktop-app/RELEASE-2.5.0.md`; развёрнутые примечания релизов — `desktop-app/RELEASE-2.5.0.md`, `RELEASE-2.5.8.md`, `RELEASE-2.5.9.md`).

## [2.6.4] — 2026-10-13

Три UX-улучшения по конкретным отзывам пользователя: живой индикатор фильтров узлов, умный выбор эндпоинта в конфиге, сквозной I1 из поиска параметров.

- Все платформы: шапка карточки «Фильтры узлы» (скан) — вместо вечной статичной надписи «DME исключён» живой бейдж активных фильтров: `✗ DME` (исключены), `✓ HEL` («только узлы»), страны — с пометкой `(страны)`; нет активных фильтров — бейдж скрыт; обновляется в реальном времени на любое изменение полей (input/change/пресеты/applyFoundCmd/init/смена языка — хук в updateCmdPreview), полный список — в tooltip, длинный список — ellipsis (CSS .badge--filter).
- Все платформы: выбор эндпоинта во вкладке «Конфиг» перестроен группами — сверху лучший эндпоинт КАЖДОЙ ноды (отсортирован по пингу tunPing||ping; общему лучшему — ★, у каждого рядом пинг), ниже optgroup «Остальные» со всеми прочими живыми строками; после завершения скана лучший эндпоинт ставится в конфиг автоматически (S.cfg.endpoint + предпросмотр конфига обновляется). Группировка вынесена в чистую функцию endpointGroups (+5 юнит-тестов: приоритет tunPing, torn-исключение, узел «?», немутация входа; 80/80).
- Все платформы: I1 теперь сквозной из «Поиска параметров» — найденный find-junk КОНКРЕТНЫЙ пакет (сырой флаг `-i1` в найденной команде) больше не выбрасывается, а подставляется прямо в поле I1 конфига (S.cfg.obf.i1) с тостом; прежнее предупреждение «GUI не представляет raw-I1» упразднено. Честная подсказка под полем I1 объясняет, что скан с `-gen-i1` генерирует пакет на лету и в отчёт не выносит (вытащить его из скана невозможно), а конкретный I1 даёт find-junk → «Применить найденное».
- Тесты: 75 → 80 (tests/endpoints.test.js: группировка ×4, сквозной I1 ×1).

## [2.6.3] — 2026-10-13

Точечный фикс регресса 2.6.2: ложные «warpscout: не найден» / «версию получить не удалось» при живом exe (отчёт пользователя).

- Все платформы: проверка warpscout снова проходит на машинах, где Neutralino теряет exit-событие spawnedProcess. Механика регресса: FE-3 (2.6.2) сделал synthetic exit двухтактным (2 × 5 с), а у проверки версии собственный таймаут был 8 с — процесс «сдавался» с exitCode = null раньше синтетики, и гейт F37 (exit 0/143/-1) отвергал валидный ответ `warpscout version` из stdout. В 2.6.1 свип был однотактным (5 с < 8 с) и успевал — потому «вернулась» старая ошибка. Фикс: таймаут проверки поднят до 12 с (больше свипа), а exitCode = null прощается ТОЛЬКО когда процесс убит нашим таймаутом (killProc не синтезирует exit); настоящий ненулевой код (антивирус-обёртка) по-прежнему отвергается. +5 юнит-тестов (wscheck.test.js: потерянный exit, штатный exit 0, реальный ненулевой код, мусор в stdout, файл не найден); тест регресса проверен на старой логике гейта (падает — ловит).
- Все платформы: устранён плавающий дефект «после запуска несколько секунд интерфейс не отвечает» (отчёт пользователя). Причина: привязка кнопок (bindEvents) выполнялась ПОСЛЕ цепочки последовательных await'ов стартовой инициализации (restoreState → computePaths → repairUdfJunction → migrateAndroidLegacyData), а нативные вызовы Neutralino обрабатываются по очереди — на медленном диске/при активном антивирусе цепочка растягивалась на секунды, и всё это время интерфейс был глух к нажатиям (плавающий характер — зависимость от состояния диска/антивируса). Фикс (QUAL-2): setupTouchUi + bindEvents выполняются сразу при разборе скриптов (preInitUi, ещё до готовности рантайма; у обоих — самозащита от двойного вызова), миграции repairUdfJunction/migrateAndroidLegacyData идут параллельно и больше не задерживают ни привязку кнопок, ни loadAccount.

Харденинг по итогам полного аудита v2.6.1 (79 находок: 0 P1 — волны P2/P3 закрыты полностью, P4 — попутно) и перевод i18n на ключи-идентификаторы (закрыта последняя находка прежнего аудита QUAL-1).

- Все платформы: командная граница перестроена — единая точка `argPath()` для всех 6 мест передачи путей в warpscout (Windows: `cmdWinPath` + кавычки; POSIX/Android: кавычки с семантикой sh, не PowerShell) (FE-1/FE-23); `restoreState` валидирует `theme/lang` по перечислению и патчит состояние только из валидных полей (FE-20); импорт пресетов — санитизация типов/лимитов/прототипа и лимит 2 МБ до парсинга (FE-4); `computePaths` больше не затирает пользовательский `wsPath` — конфликт решается явным тостом (корень регресса 2.3.0 устранён конструктивно) (FE-21); synthetic-exit моста шлётся только после двух тиков подряд — синтетика не затирает реальный код выхода (FE-3); остатки хардкода RU в touch-Home переведены (FE-24).
- Все платформы: аккаунт WARP — права файла 0600 после каждой записи/регистрации + ротация бэкапов (N=3) (SEC-A1); удаление аккаунта уносит и отчёты — копия/проверка/удаление источника (FE-22); автомиррор файла аккаунта в `Download` убран — публично выгружаются только отчёты и конфиги (FE-25); альтернативный CWD-кандидат применяется только после явного подтверждения пользователем (SEC-A4).
- Android: `content://` в openPath проходит тот же `uriAllowed`-гейт, что и файловые операции моста (AND-1); имена файлов санитизируются при записи в публичные корни `Download/WARPScoutGUI` (AND-4); ядро сборки (`libwarpscout.so`) сверяется по SHA-256 с пином `tools/deps.json` (AND-2); пароль keystore передаётся через окружение, не argv (AND-3); versionCode — единая формула `major*10000+minor*100+patch` (2.6.2 → 20602) (INFRA-F); javac-ошибки больше не глотаются (INFRA-J).
- Инструментарий/CI: `verify-deps.py` падает при «0 проверено» (INFRA-A); `fetch-binaries.py` — `curl -f`, `Accept: application/octet-stream`, проверки магии/размера, android-ядро в цепочке поставки (INFRA-B/C); `build-zips.py` сверяет версию с единым источником и печатает футер README.txt из него же (INFRA-D/E); `release.sh` — pre-flight fail-fast (INFRA-G), CI-гейт на коммите тега (INFRA-H), секреты в одном mktemp-каталоге 0700 с trap-очисткой, токен только через `--header @файл` (INFRA-K/SEC-A5); workflow `release.yml` на тег `v*` — полный набор проверок, детерминизм `resources.neu`, сборка release-zip тем же конвейером (INFRA-H); канонический `tools/sync-demo.sh` (INFRA-L); `tools/check-i18n.py` — словарь/вызовы/статика/плат-связки; `tests/structure.test.js` — состав и порядок script-тегов (QUAL-C).
- Браузерное демо (gh-pages): на смартфонах включается родной touch-интерфейс приложения — `tools/sync-demo.sh` добавляет в демо-копию `js/demo-touch.js`, который до первого рендера перезаписывает URL на штатный `?touch=1` (тот же режим, что в Android-APK: нижняя навигация, главная с быстрыми действиями); ресурсы приложения (`desktop-app/resources`) не изменяются — на десктопе вид прежний, `?touch=0` — явный escape.
- Тесты: 50 → 70 — round-trip «злого» пути через sh-токенизатор на 3 платформах, `restoreState`, `migrateData`, `computePaths`, `hardenAccountPerms`, структура пакета.
- Документация: README — пересказ изменений прошлых версий убран (история в CHANGELOG), раздел «Тесты», раздел Android-хранилища переписан по факту v2.6.x (приватная папка приложения + зеркальная копия `Download/WARPScoutGUI` через MediaStore, разрешение — только `INTERNET`).

## [2.5.0] — 2026-10-11

Кроссплатформенный пререлиз: единая кодовая база для шести платформ (развёрнуто — `desktop-app/RELEASE-2.5.0.md`).

- Windows x86_64: изменений функциональности нет — рефакторинг платформенного слоя без смены поведения (доказан построчной сверкой с 2.4.6 и живыми регрессионными прогонами); пакеты переименованы в формат «имя-OS-архитектура», лицензии вынесены в `licenses/`.
- Linux x86_64 / Linux ARM64: новая платформа — платформенный слой (`~/.local/share`, chmod +x вместо Unblock-File), WebKitGTK-зависимости документированы; ядро warpscout ARM64 проверено под эмуляцией (version/register/scan/отчёт).
- macOS arm64 (Apple Silicon) / macOS x64 (Intel): новая платформа — Darwin-слой (`~/Library/Application Support`, подсказки Gatekeeper `xattr -cr`), системный WKWebView без внешних зависимостей.
- Android ARM64: новая платформа — APK с сенсорным UI (вкладки внизу, главная с основными действиями), warpscout упакован как `lib/arm64-v8a/libwarpscout.so`, фиксированный ключ подписи — обновление поверх без потери данных (versionCode 20500).
- Выпуск прошёл сквозной аудит по методике 2.4.6 (исправлены A1–A6 и B1–B5, включая P1 — путь native lib в APK); win-инвариантность против 2.4.6 доказана структурно и живыми прогонами; политика «все платформы в каждом релизе» зафиксирована как постоянная.
