# Changelog

[English](CHANGELOG.en.md) | Русский

Все заметные изменения WARPScoutGUI-AWG фиксируются здесь; порядок — обратный хронологический, дата версии = дата релизного коммита в git.

Политика выпуска (с 2.5.0): каждый релиз содержит артефакты всех поддерживаемых платформ под единым номером версии — с указанием, что изменено на каждой платформе, либо с явной фиксацией отсутствия изменений; все выпуски 2.5.x публикуются на GitHub со статусом prerelease (блок «Политика выпуска» — `docs/RELEASE-2.5.0.md`; развёрнутые примечания релизов — `docs/RELEASE-2.5.0.md`, `RELEASE-2.5.8.md`, `RELEASE-2.5.9.md`).

## [2.8.3] — 2026-11-27 (prerelease)

Пресет «Жёсткая сеть» снова отличается от «По умолчанию» (запрос пользователя): после смены дефолта I1 на QUIC в 2.8.2 они совпали символ в символ — историческое отличие пресета было ровно в `genI1:"quic"`.

- Все платформы: **пресет «Жёсткая сеть» — автоподбор профиля I1 + таймаут зонда 4 с.** Отличие от «По умолчанию» теперь ровно два поля и оба соответствуют названию: тумблер «Автоподбор профиля I1» — если маскировка не прошла и скан ничего не нашёл, та же сессия сама перебирает профили «If nothing works» из README ядра (quic → dns → sip → stun → random), пока не найдёт рабочий (сработавший профиль остаётся в конструкторе); и `-t 4` вместо дефолтных 2 с — на жёсткой сети ответы на зонды приходят медленнее, и часть живых эндпоинтов раньше отсекалась по таймауту. Команда «Жёсткая сеть»: `warpscout scan -p awg31 -P -gen-i1 quic -t 4 -n 10 -exclude-node DME` (+ автоподбор в приложении). Удаление пресета не потребовалось — в отличие от «Тщательного» (дубль тумблера `-f`), автоподбор меняет поведение ПОСЛЕ пустого скана, а не дублирует один флаг.
- Тесты: 167 → 168 (hard-пресет — autoI1:true, timeout:4, стартовый genI1 quic, `-t 4` в команде buildScanCmd, ровно два отличия от DEFAULT_SCAN по снапшоту).
- Совместимость: форматы данных не менялись (пресет — предустановка полей формы; свои пресеты и бэкапы не затронуты).

## [2.8.2] — 2026-11-27 (prerelease)

Четыре пункта по итогам проверки пререлизов 2.8.0/2.8.1 (запросы пользователя): ручной ввод флагов CLI («вариант 1» — консоль-стиль), удаление пресета «Тщательный», управление AWG 3.1 прямо на вкладке «Скан» и дефолт профиля I1 — QUIC. Бонусом — починка мультизначных фильтров (запятые в значениях).

- Все платформы: **«Свои флаги CLI» (вариант 1)** — новая карточка на вкладке «Скан»: поле свободного ввода флагов warpscout в консоль-стиле для всего, чего нет в форме (`-sweep-ports 2408,500`, `-mtu 1280`, `-dns 1.1.1.1`, `-table-off`, `-emoji`, `-conf out.conf -conf-type mihomo`, `-I`/`-interface`, `-best`, `-no-dns`). Валидация по белому списку на границе команды (parseExtraArgs): неизвестные флаги, позиционный мусор, битые значения — явная ошибка с указанием токена (строка под полем + тост при запуске), дубли флагов, которые GUI расставляет сам (-p, -P, -gen-i1, тайминги, -jc…, -speed, -o/-a/-json/-stream-json/-plain/-no-report) не проходят с объяснением. Значение value-флага-дубля съедается («-p awg» — одна ошибка, без ложного «awg — не флаг»). Запуск при ошибках отвергается целиком (раньше половина аргументов отваливалась бы молча). Санитизация: одна строка, переводы строк/табы → пробелы, контрольные символы вырезаны, лимит 500. Map'ы белых списков — без прототипа (ключ «-constructor» не протаскивается).
- Все платформы: **пресет «Тщательный» удалён** — дубль тумблера «Все 256 адресов подсети `-f`» (полный скан включается тем же тумблером, «Замер скорости» рядом): два пути к одному и тому же только путали. Остальные пресеты (По умолчанию/Быстрый/Без обфускации/Жёсткая сеть) и свои пресеты — без изменений.
- Все платформы: **AWG 3.1 — вкл/выкл и тайминги прямо на вкладке «Скан».** В карточке «Обфускация AmneziaWG» появился тумблер «Тайминги AWG 3.1 (`-p awg31`)» и раскрывающийся блок таймингов (ContentPaddingAddition, RekeyAfterTime, RekeyTimeout, RejectAfterTime, KeepaliveTimeout, MaxHandshakeAttempts, RandomTrailers, DisableCookies). Значения — ТЕ ЖЕ общие источники, что и раньше: тумблер = «Конфиг → Версия» (S.cfg.ver, выключение возвращает скан и конфиг к AWG 2.0), тайминги = S.cfg.obf — правка синхронно меняет обе вкладки и предпросмотр (как junk-поля в 2.7.0). Все чтения формы делаются до любых записей-зеркал — «война зеркал» внутри одного sync исключена; смена версии на «Конфиге» (в т.ч. импорт .conf/бэкапа) мгновенно гасит/включает тумблер на «Скан».
- Все платформы: **дефолт профиля I1 скана — QUIC вместо iCloud** (как в других warpscout GUI — неспроста: QUIC-маскировка первого пакета чаще проходит). «iCloud (базовый)» остался опцией сегмента. Одноразовая миграция для старых установок: сохранённое genI1:"" поднимается до quic ровно один раз (флаг settings.i1QuicMigrated) — сделанный позже явный выбор (в т.ч. icloud) не трогается; старые бэкапы/пресеты БЕЗ поля получают новый дефолт, явное «""» сохраняется. Демо-сценарий автоподбора I1 адаптирован (пустой первый скан теперь именно с профилем quic).
- Все платформы: **фикс мультизначных фильтров** — safeVal больше не вырезает запятые из значений: CLI сплитит `-exclude-node`/`-exclude-country`/`-target` по запятой (splitList в flags.go ядра), а раньше «DME,FRA» и «ip,cidr» склеивались в мусорный один токен (плейсхолдеры форм прямо предлагали неработающий формат). Спавн идёт через CreateProcess (Windows) — запятая argv не режет; на POSIX спавн через /bin/sh -c, поэтому `$`, `\`, `#` теперь вырезаются всегда (подстановка переменных/комментарий в хвосте).
- Тесты: 152 → 167 (parseExtraArgs — белый список/дубли с arity/неизвестные/позиционные/битые значения/prototype-ключи; buildScanArgs — свои флаги в конце до -plain; runScan — отказ при невалидных своих флагах; sanitizeScan — extraArgs-строка и дефолт genI1; restoreState — одноразовая миграция quic; safeVal — запятые сохраняются, $ \ # вырезаются; тумблер fUse31 ↔ cfg.ver в обе стороны + «война зеркал» исключена; тайминги 3.1 синхронны Скан↔Конфиг).
- Совместимость: форматы данных не менялись (extraArgs — новое строковое поле профиля скана, дефолт ""; миграция genI1 — одноразовая, явные выборы сохраняются). Отчёты, конфиги, аккаунт, история, бэкапы — без изменений.

## [2.8.1] — 2026-11-27 (prerelease)

Три точечных исправления по итогам проверки пререлиза 2.8.0 (отчёт пользователя): двойной скролл на вкладках «Скан»/«Конфиг», спрятанные в «продвинутых» тумблеры скорости и звезда «лучшего», достававшаяся эндпоинтам с потерями.

- Все платформы (десктоп): **вкладки «Скан» и «Конфиг» без скролла страницы.** Раньше у этих вкладок было два независимых скролла — сама страница (.main) и колонка параметров: прокрутка страницы уводила настройки за верхний край (колонка «пряталась», оставаясь хвостом у нижней части экрана), а правая колонка (результаты / предпросмотр+экспорт) тянула высоту документа за собой. Теперь в двухколоночном десктоп-виде страница не скроллится вовсе: сетка строкой `minmax(0, 1fr)` прижимает ОБЕ колонки к высоте вьюпорта, каждая скроллится только внутри себя — слева параметры, справа командная строка+таблица (пл. предпросмотр+экспорт — целиком на одном экране). Таблица результатов и лог занимают ровно оставшееся место (flex) вместо прежних эвристик `max-height: calc(100vh - …)`. Порог 1081px — над существующим переходом в одноколоночный вид; мобильная вёрстка и touch-режим (Android, демо `?touch=1`) не затронуты — там по-прежнему скроллится страница.
- Все платформы: **«Замер скорости» и «Лучший по скорости» подняты в основную группу флагов** — из details-карточки «WARP-in-WARP и продвинутое» в карточку «Проверка и выборка», рядом с `-P`/`-f`, с короткими подсказками (в том числе что `-best-by speed` включает замер). Состояние и билдер команды не менялись — только положение в DOM и две новых подсказки словаря (RU/EN).
- Все платформы: **звезда «лучшего» сначала смотрит на потери, потом на пинг.** Сравнение качества строки — лексикографичное (LOSS, PING) — ровно как сортирует сам warpscout в отчёте: эндпоинт без потерь всегда впереди lossy с меньшим пингом (0% потерь важнее десятков мс), среди lossy меньше потерь лучше, при равных — меньший пинг. Нет колонки LOSS (скан без `-P`) — сравнение вырождается в прежнее «минимальный пинг». Порядок применён во всех местах выбора лучшего: звезда в таблице, группировка селекта конфига (лучший каждой ноды + общий), автоподстановка в конфиг после скана, кнопка «★ Лучший» в SOCKS, звезда в автономном HTML-отчёте. «Лучший по скорости» (`-best-by speed`) тоже учитывает потери: максимум SPEED ищется сначала среди строк без потерь, фолбэк — среди lossy. Чип статистики «⚡ лучший» переименован в «⚡ мин. пинг» — это по-прежнему минимум TUN PING по выборке, теперь он не читается как «позиция звезды».
- Тесты: 148 → 152 (endpointGroups — без потерь впереди lossy с меньшим пингом и в лучах нод, «остальные» по (потери, пинг); betterEpRow/rowLossVal — порядок (потери, пинг), пустой/мусорный LOSS → 0; bestBySpeedOf — максимум SPEED среди без потерь, фолбэк на lossy, прежняя семантика без колонки LOSS; pickRunBest — без потерь важнее меньшего пинга).
- Совместимость: форматы данных не менялись (отчёты, история, бэкапы). Меняется только выбор «лучшего»: при наличии строки с LOSS>0 у более «пингового» эндпоинта звезда и автоподстановка уходят на безпотерьную строку.

## [2.8.0] — 2026-11-27 (prerelease)

Пакет улучшений по итогам разбора трёх сторонних GUI для warpscout (HattabbI4, 3inker, openwarpkit): живая таблица скана, банер новой версии самого GUI, два новых формата экспорта, автоподбор профиля I1 и повтор скана из истории. **Выпуск опубликован как PRERELEASE** — после проверки переводится в полноценный релиз (GitHub API: prerelease=false, make_latest=true; эндпоинт releases/latest пререлизы не отдаёт, поэтому банер обновления на этот выпуск у пользователей 2.7.3 не сработает до перевода).

- Все платформы: **живая таблица скана через `-stream-json`** (флаг появился в warpscout 0.17.0). Скан теперь запускается с `-stream-json` (схема `warpscout-v1.schema.json`): события `progress` (фазы ports/tunnels/speed с точными done/total — прогресс-бар показывает реальные проценты вместо regex-догадок по тексту CLI), `endpoint` (строки появляются в таблице по мере находки, перерисовка троттлингом 800 мс), `error`, `done` (авторитетный документ результата: working/torn/picks/best). Живая панель (график, чипы узлов, счётчики) питается теми же структурированными событиями. Файл отчёта по-прежнему пишется (`-o` возвращает его явно — нужен для Android-зеркала в Download/WARPScoutGUI) и служит фолбэком. Совместимость: на warpscout <0.17 (свой CLI в «Настройках») гейт версии не добавляет флаг; если старое ядро всё же упало с «flag provided but not defined» — тихий перезапуск той же сессии в обычном режиме (файл отчёта) с примечанием в логе. В лог пишутся только вехи фаз и ошибки CLI — сырой NDJSON в журнал не льётся.
- Все платформы: **банер «⬆ WarpScoutGUI {v} — есть обновление»** (F2) — симметрично подсказке warpscout из 2.7.3: раз за сессию (не чаще раза в 12 ч, своя метка localStorage) приложение читает `releases/latest` СВОЕГО репозитория через api.github.com (тот же единственный CSP-хост, read-only без данных пользователя) и при более свежей версии показывает вторую строку в статус-линии; клик — страница релизов. GitHub не отдаёт в `releases/latest` пререлизы и черновики — банер срабатывает только на переведённые в полноценный релиз версии.
- Все платформы: **экспорт mihomo .json** (F3) — те же прокси, что в Clash .yaml (WireGuard+AmneziaWG с полным amnezia-wg-option, включая тайминги 3.1 и I1, + MASQUE-узлы при наличии устройства), но JSON-массивом (формат CLI `-conf-type mihomo-json`) — для клиентов, читающих JSON-профили; кнопка рядом с Clash/WireSock.
- Все платформы: **экспорт usque config.json** (F3, MASQUE) — формат usque требует ECDSA-ключи и license, которых нет в WG/AWG-части аккаунта, поэтому единственный честный источник — само ядро: кнопка «🪶 usque config.json» прогоняет короткий мини-скан выбранного эндпоинта (`scan -p masque -target <ip> -port <port> -n 1 -conf - -conf-type native`, механика «I1 из сканирования») и сохраняет готовый config.json через диалог. Неверный/пустой вывод — тост, ничего не пишется.
- Все платформы: **автоподбор профиля I1** (F4) — тумблер «Автоподбор профиля I1» в карточке «Обфускация AmneziaWG»: если скан AWG не нашёл ни одного рабочего эндпоинта, приложение в той же сессии само перебирает профили «If nothing works» из README ядра (quic → dns → sip → stun → random, минус текущий), показывая «Автоподбор I1: профиль {p} ({n}/{m})»; сработавший профиль остаётся в конструкторе и сообщается тостом. Промежуточные пустые попытки не засоряют историю (запись одна — итог цепочки); Stop останавливает цепочку; для wg/masque фича неактивна.
- Все платформы: **«Лучший по скорости» доведён до конца** (F6) — флаг `-best-by speed` в конструкторе уже был, теперь звезда лучшего в таблице, автоподстановка в конфиг после скана и кнопка «★ Лучший» в SOCKS учитывают его: при замере скорости лучшим считается эндпоинт с максимальным SPEED, а не минимальным пингом.
- Все платформы: **повтор скана из истории** (F7) — в записях истории снимок параметров хранился с 2.4.6, но доставить его было нельзя: кнопка «⟳» в каждой записи возвращает параметры в конструктор (форма не запускается сама — запуск остаётся за пользователем), с клавиатурой и тостом-подтверждением.
- Все платформы (десктоп): **предупреждение при закрытии окна с активным SOCKS** (F8) — событие `windowClose` перехватывается: при запущенном SOCKS-прокси окно спросит «Закрыть приложение и остановить прокси?», при отказе остаётся открытым; состояние сохраняется на диск перед выходом. Фикс: кавычко-осведомлённая токенизация (`/"[^"]*"|"[^"]*$|\S+/g`, незакрытая кавычка — до конца строки), лимиты 1000→8000 (команда) и 600→6000 (значение, как в QC/sanitize), shell-кавычки снимаются (как и при импорте .conf — parseConfText), raw-форма `<b …>` хранится и выводится в конфиг как есть; прочим форматам (base64) пробелы вычищаются как раньше. Попутно починен давний дефект дефолта: эталонный EXAMPLE_I1 в предпросмотре/экспорте больше не теряет пробел после `<b`. Лимит восстановления foundCmd из storage поднят 500→8000 — найденная команда переживает перезапуск приложения целиком.
- Тесты: 88 → 92 (tests/endpoints.test.js: raw-I1 в кавычках с пробелом доезжает до конфига целиком (регресс отчёта), незакрытая кавычка — до конца строки, чистый normI1Store/isI1RawPacket ×1, buildConf raw/base64 ×1); браузерная верификация демо: применённая команда с raw-I1 (2566 симв.) — поле I1 и предпросмотр совпадают байт-в-байт, значение переживает перезагрузку страницы; дефолтный EXAMPLE_I1 в предпросмотре — целиком с пробелом.

## [2.5.0] — 2026-10-11

Кроссплатформенный пререлиз: единая кодовая база для шести платформ (развёрнуто — `docs/RELEASE-2.5.0.md`).

- Windows x86_64: изменений функциональности нет — рефакторинг платформенного слоя без смены поведения (доказан построчной сверкой с 2.4.6 и живыми регрессионными прогонами); пакеты переименованы в формат «имя-OS-архитектура», лицензии вынесены в `licenses/`.
- Linux x86_64 / Linux ARM64: новая платформа — платформенный слой (`~/.local/share`, chmod +x вместо Unblock-File), WebKitGTK-зависимости документированы; ядро warpscout ARM64 проверено под эмуляцией (version/register/scan/отчёт).
- macOS arm64 (Apple Silicon) / macOS x64 (Intel): новая платформа — Darwin-слой (`~/Library/Application Support`, подсказки Gatekeeper `xattr -cr`), системный WKWebView без внешних зависимостей.
- Android ARM64: новая платформа — APK с сенсорным UI (вкладки внизу, главная с основными действиями), warpscout упакован как `lib/arm64-v8a/libwarpscout.so`, фиксированный ключ подписи — обновление поверх без потери данных (versionCode 20500).
- Выпуск прошёл сквозной аудит по методике 2.4.6 (исправлены A1–A6 и B1–B5, включая P1 — путь native lib в APK); win-инвариантность против 2.4.6 доказана структурно и живыми прогонами; политика «все платформы в каждом релизе» зафиксирована как постоянная.
