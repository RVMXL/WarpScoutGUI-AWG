# Changelog

English | [Русский](CHANGELOG.md)

All notable changes to WARPScoutGUI-AWG are recorded here; the order is reverse chronological, the version date = the date of the release commit in git.

Release policy (since 2.5.0): every release contains the artifacts of all supported platforms under a single version number — stating what changed on each platform, or explicitly recording that nothing changed; all 2.5.x releases are published on GitHub with the prerelease status (the "Release policy" block — `desktop-app/RELEASE-2.5.0.md`; extended release notes — `desktop-app/RELEASE-2.5.0.md`, `RELEASE-2.5.8.md`, `RELEASE-2.5.9.md`).

- Repository: **README and CHANGELOG — Russian by default, with a link to the English versions at the top.** README.en.md and CHANGELOG.en.md are full synchronized translations; the "English | Русский" cross-links in the headers of both files — as customary in multilingual repositories.
- Tests: 168, all green (an i18n-layer edit with no new pure functions; the android phrases are covered by the check-i18n dictionary).
- Compatibility: data formats unchanged; the edit is textual — it does not affect the scan command, reports, configs, the account, history or backups.
- Release status: **a full release** (prerelease=false, make_latest=true) — releases/latest now returns 2.8.4, so the "⬆ WarpScoutGUI" banner will trigger for users of 2.7.3/2.8.0/2.8.1/2.8.2/2.8.3. ## [2.8.3] — 2026-11-27 (pre-release)

The "Hard network" preset differs from "Default" again (user request): after the I1 default changed to QUIC in 2.8.2 the two matched character for character — the preset's historic difference was exactly `genI1:"quic"`.

- All platforms: **the "Hard network" preset — I1 profile auto-pick + a 4 s probe timeout.** The difference from "Default" is now exactly two fields, and both match the name: the "I1 profile auto-pick" toggle — if the disguise did not get through and the scan found nothing, the same session itself iterates the "If nothing works" profiles from the core README (quic → dns → sip → stun → random) until it finds a working one (the profile that worked stays in the builder); and `-t 4` instead of the default 2 s — on a hard network probe responses arrive slower, and some live endpoints used to be cut off by the timeout. The "Hard network" command: `warpscout scan -p awg31 -P -gen-i1 quic -t 4 -n 10 -exclude-node DME` (+ auto-pick in the app). Removing the preset was not needed — unlike "Thorough" (a duplicate of the `-f` toggle), auto-pick changes behavior AFTER an empty scan rather than duplicating a single flag.
- Demo: rebuilt from the resources (sync-demo 28a4); no behavioral scenarios were added.
- Tests: 167 → 168 (the hard preset — autoI1:true, timeout:4, the starting genI1 quic, `-t 4` in the buildScanCmd command, exactly two differences from DEFAULT_SCAN per the snapshot).
- Compatibility: data formats unchanged (a preset is a pre-setting of the form fields; custom presets and backups are not affected).

## [2.8.2] — 2026-11-27 (pre-release)

Four items based on the verification of the 2.8.0/2.8.1 pre-releases (user requests): manual input of CLI flags ("option 1" — console style), removal of the "Thorough" preset, AWG 3.1 control right on the "Scan" tab, and the I1 profile default — QUIC. As a bonus — a fix for multi-value filters (commas in values).

- All platforms: **"Custom CLI flags" (option 1)** — a new card on the "Scan" tab: a free-form field for warpscout flags in console style for everything that is not in the form (`-sweep-ports 2408,500`, `-mtu 1280`, `-dns 1.1.1.1`, `-table-off`, `-emoji`, `-conf out.conf -conf-type mihomo`, `-I`/`-interface`, `-best`, `-no-dns`). Whitelist validation at the command boundary (parseExtraArgs): unknown flags, positional garbage, broken values — an explicit error naming the token (a line under the field + a toast on launch); duplicates of the flags the GUI places itself (-p, -P, -gen-i1, the timings, -jc…, -speed, -o/-a/-json/-stream-json/-plain/-no-report) do not pass, with an explanation. The value of a duplicate value-flag is consumed ("-p awg" — one error, without a false "awg is not a flag"). A launch with errors is rejected in full (previously half of the arguments would have silently dropped off). Sanitization: a single line, newlines/tabs → spaces, control characters stripped, a limit of 500. The whitelist maps are prototype-free (the "-constructor" key does not slip through).
- All platforms: **the "Thorough" preset removed** — a duplicate of the "All 256 subnet addresses `-f`" toggle (the full scan is enabled by the same toggle, "Speed measurement" is nearby): two paths to the same thing only confused. The other presets (Default/Fast/No obfuscation/Hard network) and custom presets — unchanged.
- All platforms: **AWG 3.1 — on/off and the timings right on the "Scan" tab.** The "AmneziaWG obfuscation" card gained an "AWG 3.1 timings (`-p awg31`)" toggle and an expandable timings block (ContentPaddingAddition, RekeyAfterTime, RekeyTimeout, RejectAfterTime, KeepaliveTimeout, MaxHandshakeAttempts, RandomTrailers, DisableCookies). The values are THE SAME shared sources as before: the toggle = "Config → Version" (S.cfg.ver; switching it off returns the scan and the config to AWG 2.0), the timings = S.cfg.obf — an edit changes both tabs and the preview in sync (like the junk fields in 2.7.0). All form reads happen before any mirror writes — a "mirror war" within a single sync is excluded; changing the version on the "Config" tab (including importing a .conf/backup) instantly extinguishes/enables the toggle on "Scan".
- All platforms: **the default I1 profile of the scan — QUIC instead of iCloud** (as in the other warpscout GUIs — for a reason: QUIC disguise of the first packet gets through more often). "iCloud (basic)" remains a segment option. A one-time migration for old installs: a saved genI1:"" is raised to quic exactly once (the settings.i1QuicMigrated flag) — an explicit choice made later (including icloud) is not touched; old backups/presets WITHOUT the field get the new default, an explicit '""' is preserved. The I1 auto-pick demo scenario was adapted (the empty first scan is now with the quic profile exactly).
- All platforms: **a fix for multi-value filters** — safeVal no longer strips commas from values: the CLI splits `-exclude-node`/`-exclude-country`/`-target` on commas (splitList in the core's flags.go), while previously "DME,FRA" and "ip,cidr" were glued into a single garbage token (the form placeholders outright suggested a format that did not work). The spawn goes through CreateProcess (Windows) — a comma is not cut from argv; on POSIX the spawn is via /bin/sh -c, so `$`, `\`, `#` are now always stripped (variable substitution/a comment in the tail).
- Demo: rebuilt from the resources (sync-demo 28a3); no behavioral scenarios were added (apart from adapting the I1 auto-pick to the new default).
- Tests: 152 → 167 (parseExtraArgs — whitelist/duplicates with arity/unknown/positional/broken values/prototype keys; buildScanArgs — custom flags at the end, before -plain; runScan — refusal on invalid custom flags; sanitizeScan — the extraArgs string and the genI1 default; restoreState — the one-time quic migration; safeVal — commas preserved, $ \ # stripped; the fUse31 toggle ↔ cfg.ver in both directions + a "mirror war" excluded; the 3.1 timings synchronized Scan↔Config).
- Compatibility: data formats unchanged (extraArgs — a new string field of the scan profile, default ""; the genI1 migration is one-time, explicit choices are preserved). Reports, configs, the account, history, backups — unchanged.

## [2.8.1] — 2026-11-27 (pre-release)

Three targeted fixes based on the verification of the 2.8.0 pre-release (a user report): the double scroll on the "Scan"/"Config" tabs, the speed toggles hidden in "advanced", and the "best" star that went to endpoints with losses.

- All platforms (desktop): **the "Scan" and "Config" tabs without page scrolling.** Previously these tabs had two independent scrolls — the page itself (.main) and the parameters column: scrolling the page pushed the settings past the top edge (the column "hid", remaining as a tail near the bottom of the screen), while the right column (results / preview+export) dragged the document height along with it. Now in the two-column desktop view the page does not scroll at all: a grid with the row `minmax(0, 1fr)` presses BOTH columns to the viewport height, each scrolling only inside itself — parameters on the left, the command line+table on the right (plus preview+export — entirely on one screen). The results table and the log occupy exactly the remaining space (flex) instead of the former `max-height: calc(100vh - …)` heuristics. The 1081px threshold sits above the existing transition to the single-column view; the mobile layout and the touch mode (Android, the demo `?touch=1`) are not affected — there the page still scrolls.
- All platforms: **"Speed measurement" and "Best by speed" moved up into the main flag group** — from the details card "WARP-in-WARP and advanced" into the "Check and sample" card, next to `-P`/`-f`, with short hints (including that `-best-by speed` enables the measurement). The state and the command builder were not changed — only the position in the DOM and two new dictionary hints (RU/EN).
- All platforms: **the "best" star looks at losses first, then at ping.** The row quality comparison is lexicographic (LOSS, PING) — exactly how warpscout itself sorts in the report: an endpoint without losses is always ahead of a lossy one with a lower ping (0% losses matter more than tens of ms), among lossy ones fewer losses is better, on a tie — a lower ping. No LOSS column (a scan without `-P`) — the comparison degrades to the former "minimal ping". The order is applied in every place where the best is picked: the star in the table, the grouping of the config select (the best of each node + the overall best), the auto-fill into the config after a scan, the "★ Best" button in SOCKS, the star in the standalone HTML report. "Best by speed" (`-best-by speed`) also accounts for losses: the maximum SPEED is sought first among the rows without losses, with a fallback to the lossy ones. The "⚡ best" statistics chip has been renamed to "⚡ min. ping" — it is still the minimum TUN PING over the sample, but now it is not read as "the star's position".
- Demo: rebuilt from the resources (sync-demo 28a2).
- Tests: 148 → 152 (endpointGroups — no-losses ahead of a lossy one with a lower ping, and within node beams; "the rest" by (losses, ping); betterEpRow/rowLossVal — the (losses, ping) order, an empty/garbage LOSS → 0; bestBySpeedOf — the maximum SPEED among the no-loss rows, a fallback to lossy, the former semantics without a LOSS column; pickRunBest — no losses matter more than a lower ping).
- Compatibility: data formats unchanged (reports, history, backups). Only the choice of "the best" changes: when a row with LOSS>0 exists, for a more "ping-y" endpoint the star and the auto-fill move to the loss-free row.

## [2.8.0] — 2026-11-27 (pre-release)

A package of improvements based on the analysis of three third-party GUIs for warpscout (HattabbI4, 3inker, openwarpkit): a live scan table, a new-version banner for the GUI itself, two new export formats, I1 profile auto-pick, and re-running a scan from history. **The release is published as a PRERELEASE** — after verification it is converted to a full release (GitHub API: prerelease=false, make_latest=true; the releases/latest endpoint does not serve pre-releases, so the update banner will not trigger on this release for users of 2.7.3 until the conversion).

- All platforms: **a live scan table via `-stream-json`** (the flag appeared in warpscout 0.17.0). The scan now runs with `-stream-json` (the `warpscout-v1.schema.json` schema): `progress` events (the ports/tunnels/speed phases with exact done/total — the progress bar shows real percentages instead of regex guesses over the CLI text), `endpoint` (rows appear in the table as they are found, with the redraw throttled at 800 ms), `error`, `done` (the authoritative result document: working/torn/picks/best). The live panel (the chart, the node chips, the counters) is fed by the same structured events. The report file is still written (`-o` returns it explicitly — it is needed for the Android mirror into Download/WARPScoutGUI) and serves as a fallback. Compatibility: on warpscout <0.17 (a custom CLI in "Settings") the version gate does not add the flag; if the old core still fails with "flag provided but not defined" — a silent restart of the same session in the regular mode (the report file) with a note in the log. Only phase milestones and CLI errors go to the log — raw NDJSON is not poured into the journal.
- All platforms: **the "⬆ WarpScoutGUI {v} — an update is available" banner** (F2) — symmetric to the warpscout hint from 2.7.3: once per session (no more than once in 12 h, with its own localStorage mark) the app reads `releases/latest` of ITS OWN repository via api.github.com (the same single CSP host, read-only, without user data) and, on a fresher version, shows a second line in the status line; a click opens the releases page. GitHub does not serve pre-releases or drafts in `releases/latest` — the banner triggers only on versions converted to a full release.
- All platforms: **mihomo .json export** (F3) — the same proxies as in Clash .yaml (WireGuard+AmneziaWG with the full amnezia-wg-option, including the 3.1 timings and I1, + MASQUE nodes when a device is present), but as a JSON array (the CLI format `-conf-type mihomo-json`) — for clients that read JSON profiles; the button sits next to Clash/WireSock.
- All platforms: **usque config.json export** (F3, MASQUE) — the usque format requires ECDSA keys and a license, which are not present in the WG/AWG part of the account, so the only honest source is the core itself: the "🪶 usque config.json" button runs a short mini-scan of the selected endpoint (`scan -p masque -target <ip> -port <port> -n 1 -conf - -conf-type native`, the "I1 from scanning" mechanics) and saves the finished config.json through a dialog. Invalid/empty output — a toast, nothing is written.
- All platforms: **I1 profile auto-pick** (F4) — an "I1 profile auto-pick" toggle in the "AmneziaWG obfuscation" card: if an AWG scan found no working endpoint at all, the app itself, in the same session, iterates the "If nothing works" profiles from the core README (quic → dns → sip → stun → random, minus the current one), showing "I1 auto-pick: profile {p} ({n}/{m})"; the profile that worked stays in the builder and is reported with a toast. Intermediate empty attempts do not clutter the history (there is a single entry — the outcome of the chain); Stop halts the chain; the feature is inactive for wg/masque.
- All platforms: **"Best by speed" carried through to the end** (F6) — the `-best-by speed` flag was already in the builder; now the best star in the table, the auto-fill into the config after a scan, and the "★ Best" button in SOCKS account for it: with a speed measurement on, the endpoint with the maximum SPEED is considered the best, not the one with the minimal ping.
- All platforms: **re-running a scan from history** (F7) — the history entries have stored a snapshot of the parameters since 2.4.6, but there was no way to deliver it: the "⟳" button in each entry returns the parameters to the builder (the form does not launch itself — launching remains with the user), keyboard-accessible and with a confirmation toast.
- All platforms (desktop): **a warning when closing the window with active SOCKS** (F8) — the `windowClose` event is intercepted: with a SOCKS proxy running, the window will ask "Close the app and stop the proxy?", and on refusal it stays open; the state is saved to disk before exiting. The demo and Android are not affected.
- Demo mode: an NDJSON `-stream-json` scenario (the same data as in the text report, including the variation), the I1 auto-pick toggle adapts the demo's empty scan (the first run without a profile is empty, with a profile — it finds addresses), the GUI banner is shown on a fictional "v2.9.0", the usque button returns a fictional config.json.
- Tests: 134 → 148 (stream.test.js — wsSupports/wsSupportsStream (a semver gate at 0.17.0), buildScanCmd (-stream-json only by the gate and opts, -o preserved), streamParseLine (schema events; garbage/truncations/non-objects → null), streamNum (ms/%, the speed with 1 decimal, null/NaN/Infinity → empty), streamEpToRow (the full conversion; null fields → empty columns; the loc "city, country"; non-ip:port → null), streamDoneToResults (working+torn in the CLI order, torn forced, best/picks), autoI1Candidates (the "If nothing works" order, minus the current one), bestBySpeedOf (the maximum SPEED among the working ones; torn/unmeasured skipped), pickRunBest (F6: with the flag — speed-based, without — ping-based), sanitizeScan (autoI1 truthy/falsy, the default false); guiupd.test.js — guiParseTag, guiUpdFor (the banner only for a fresher full release), buildMihomoJson (a valid array, amnezia-wg-option for awg31, the reserved cleanup, ver=wg without options, a MASQUE device → QUIC+H2)).

## [2.7.1] — 2026-11-19

Two changes by user request: the I1 used by the scan can now be put into the config with one button (a fresh packet of the same profile — so the config does not "lag behind" the scan); the "Fast" preset was rethought — it is the standard AWG scan over 3 subnet addresses, and the former wg run has been honestly renamed to "No obfuscation".

- All platforms: a new "I1 from scanning" button on the "Config → Obfuscation parameters → Advanced" tab (next to "Import I1 from .conf"). The problem: a scan with `-gen-i1` generates the init packet on the fly (per run) and does not carry it into the report — the scan shows working endpoints, while a config without I1 (or with someone else's I1) may fail to connect in the same network. The solution: warpscout prints the CONCRETE packet in the output of `scan -conf -` — verified on the real CLI both for the `-gen-i1 quic/dns/sip/stun/random` profiles (with `-i1-sni`) and for the default iCloud probe. The button runs a mini-scan of a single endpoint (the one selected on the "Config" tab; after a scan the best one is placed there) with the same profile and SNI as the last scan (a lastRunParams snapshot; junk — the same priority branch as the QC check: gen-i1 → gen-junk → the shared set from S.cfg.obf), with the flags `-plain -conf - -conf-type native -no-report` (no report file and no tunnel ping) and parses the fresh I1 from stdout. The packet is rebuilt from scratch — the bytes differ, but the form/profile are the same: the config stops mismatching the scan. During the run the button is disabled and shows "…"; a repeated launch is blocked; the endpoint did not respond → an honest toast "try another endpoint"; the last run was not AWG (masque/wg) → an explanation that I1 applies only to awg scans; an "I1 = none" in the output is discarded; the hint under the I1 field has been updated. Tests 110 → 120 (i1scan.test.js — a new file: the fast/noobf presets and the hint identifiers; buildI1Cmd — three profile/junk branches; parseI1Output — raw form/CRLF/noendpoints/noi1/none/last line; finishI1 — writing to S.cfg.obf.i1 and the config field with a toast).
- All platforms: the presets of the "Scan" tab have been renamed to match their meaning (the request: "the 'fast' preset currently means a run through wg, which does not match the name"). "⚡ Fast" = the same standard AWG scan (the tunnel ping and all parameters by default), but 3 addresses per subnet instead of 10 — a run three times shorter when time is tight. The former wg run is a separate "🚫 No obfuscation" preset (wg, without -P, 5 addresses per subnet) for networks where WARP is not filtered. The preset hints have been moved to i18n dictionary identifiers: the EN translation now works for the hint under the chips too, and the hint updates on a language change.

## [2.7.0] — 2026-11-18

Three tasks from user feedback: the label overlap in the "Advanced" section of the "Config" tab has been fixed; the obfuscation parameters have been unified (one set for "Scan" and "Config"); the config generator gained an export for Clash.Meta/mihomo (WireGuard+AmneziaWG + MASQUE, per a user example) and for WireSock (the extra keys Id/Ip/Ib).

- All platforms: "Config → Obfuscation parameters → Advanced (AWG 3.1 timings)" — the ContentPaddingAddition / RekeyAfterTime / RekeyTimeout / RejectAfterTime / KeepaliveTimeout / MaxHandshakeAttempts / RandomTrailers / DisableCookies / HeaderProtectionKey grid is expanded to the full width of the card (it used to be squeezed into the right half of the outer 2-column grid, cells of ~90px), and the long unbreakable identifiers wrap character-by-character (`overflow-wrap: anywhere`) — text no longer overlaps, on desktop or in touch mode.
- All platforms: the junk parameters Jc/Jmin/Jmax are now ONE set for the scan and the config — a single source `S.cfg.obf` (the "Config" tab ↔ the "AmneziaWG obfuscation" card on the "Scan" tab are synchronized in both directions, the config preview updates immediately). The scan checks the endpoints with exactly the set that will go into the config; "Random junk" (-gen-junk) remains scan-only — it randomizes the set only for the duration of the run and does not touch the config. Junk values found in "Parameter search" are written to the shared source; the v2.4.6 (F18) blocks "a copy of the junk from the launch parameters when carrying an endpoint into the config" were removed as redundant; junk fields from old states/presets in the scan profile are ignored by the sanitizer. "🧩 Clash .yaml" — a Clash.Meta/mihomo profile per the user's example: the warp-common anchor (WireGuard with the account's keys/addresses, allowed-ips, MTU, DNS), amnezia-wg-option with all the obfuscation parameters from the "Config" tab (S1–S4, Jc/Jmin/Jmax, H1–H4, I1/I2–I5 in correct YAML quoting, for AWG 3.1 — content-padding-addition / rekey-after-time / rekey-timeout / reject-after-time / keepalive-timeout / max-handshake-attempts / random-trailers / disable-cookies), the WARP reserved bytes (optional — from a working Clash/wgcf config of the same account, cleaned down to digits), with a masque device in the account — [WARP-MASQUE] QUIC/H2 nodes, a Cloudflare group (select) and a MATCH rule. ## [2.6.8] — 2026-10-25

Another fix from a user report (a continuation of 2.6.7): a config with an I1 found in "Parameter search" would not come up — the daemon answered `IPC error -22: failed to parse i1: unknown tag <b0xc1…>` / `unknown tag <r23>`.

## [2.6.3] — 2026-10-13

A targeted fix of the 2.6.2 regression: false "warpscout: not found" / "failed to get the version" with a live exe (a user report).

- All platforms: the warpscout check passes again on machines where Neutralino loses the spawnedProcess exit event. The regression mechanics: FE-3 (2.6.2) made the synthetic exit two-tick (2 × 5 s), while the version check had its own timeout of 8 s — the process "gave up" with exitCode = null before the synthetic exit, and the F37 gate (exit 0/143/-1) rejected the valid `warpscout version` answer from stdout. - All platforms: the flaky defect "for a few seconds after launch the interface does not respond" has been eliminated (a user report). Cause: the button binding (bindEvents) ran AFTER the chain of sequential awaits of the startup initialization (restoreState → computePaths → repairUdfJunction → migrateAndroidLegacyData), and Neutralino native calls are processed one by one — on a slow disk / with an active antivirus the chain stretched into seconds, and all that time the interface was deaf to taps (the flaky nature — a dependence on the disk/antivirus state).
